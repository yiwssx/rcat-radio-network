## Backup boundary and data coverage

| Component | Source | Backup archive member |
| --- | --- | --- |
| Radio PostgreSQL database | `rcat_radio_network_postgres_data` | `volumes/postgres_data/` |
| Media library | `rcat_radio_network_libretime_storage` | `volumes/libretime_storage/` |
| Playout cache/state | `rcat_radio_network_libretime_playout` | `volumes/libretime_playout/` |
| Unique passwords, application/session keys and LibreTime config | `/etc/rcat-radio-network/` | `private/rcat-radio-network/` |
| Exact installed Compose and radio override | `/opt/rcat-libretime-runtime/*.yml` | `runtime/` |
| Non-secret snapshot description | Generated by script | `manifest.json` |

The archive contains **live credentials**. Treat it as **highly sensitive**: root-owned backup directory 0700, archive/checksum 0600, no GitHub/chat attachment, and encrypted offsite storage if moved. A same-host backup is **not** offsite disaster recovery. Retention and offsite destination remain an owner release decision.

## Approved-loop operator procedure

The versioned [RRN-06 radio-only cold backup script](../scripts/rrn06-radio-backup.py) has two explicit modes:

1. **Read-only plan:** `sudo python3 scripts/rrn06-radio-backup.py --plan`. Requires exactly the ten running radio containers, the three **project-labeled local** Docker volumes, and private files. Shows a non-secret summary only. This does not stop or restart containers and does not create backup files.
2. **Backup with explicit radio-only downtime authorization:** `sudo python3 scripts/rrn06-radio-backup.py --backup --approve-radio-outage`. This is **not** a default or unattended step. Stop **only** Compose project `rcat_radio_network`; archive its frozen volumes/config into `/var/backups/rcat-radio-network`; calculate SHA-256; restart **only** existing radio project containers in a `finally` handler. It neither creates new containers nor touches PDF HUB/AnyFlip.
3. Record only `RRN06_BACKUP=PASS`, archive filename and SHA-256 verification outcome. **Do not claim backup success based on script source alone.** If stop/archive/start fails, record exactly what happened, inspect only the radio project and **do not rerun blindly**. No `down -v`, unscoped Docker prune, global daemon restart or removal of live volumes.
4. Because a cold snapshot **interrupts radio** for the time required to archive data, obtain explicit approval for a planned station outage before invoking `--backup`. Plan-only review needs no outage approval.

**Frequency:** do not enable a timer or schedule automatically. Once the owner chooses a frequency and secure offsite destination, use the existing operating workflow; avoid introducing a new backup service.

## Restore and recovery — intentionally manual and isolated

1. On an isolated recovery machine or new radio-only project, first ensure **the destination is empty and isolated**. Never restore onto live `rcat_radio_network` volumes or extract the archive with `-C /`.
2. Keep the archive private. Verify its adjacent `.sha256` sidecar with `sha256sum --check` and review relative archive paths using `tar -tzf` (do not display any private file contents). Extract **into a newly created root-only staging directory**, never over a working application.
3. Restore the private config/Compose versions and three archived datasets into **new, correctly owned radio-only volumes** under the matching pinned LibreTime/Icecast images. Do not restore unrelated Docker applications or alter the historical `/opt/rcat-radio-network` checkout.
4. Only then, through an independently authorized recovery change, start the isolated radio project and check **one relevant recovery outcome**: the restored media/database can be used and the existing audio mount becomes usable. Confirm secrets, timestamps and operator access; do not repeat the already accepted Live DJ/fallback test unless this restore changed that subsystem.
5. Record the restore result and the exact recovery target. A saved archive and checksum without a restore exercise establish **backup creation/integrity**, not full recoverability.

**Failure boundary:** If a restore would touch current data, shared Docker Engine, public DNS/HTTPS, or any other RCAT system, STOP. Restoration to Production and the first intentional radio outage require their own explicit authorization.

## Daily operator reference

- **Current local UI:** private SSH tunnel to `127.0.0.1:8700`; never expose admin directly.
- **Current listener:** private `http://127.0.0.1:8600/main.mp3`; future HTTPS listener must be separately authorized in [RRN-05 #7](../issues/7).
- **DJ:** assigned LibreTime Show Source via `127.0.0.1:8605` SSH tunnel and `/show`; use the [existing RRN-04 SOP](./RRN-04-LIVE-DJ-SOP.md).
- **Operations:** start/stop only the named radio Compose project using its pinned runtime files and private env; do not use Docker Engine-wide operations.
- **Security:** rotate initial `admin/admin` if not already changed. Keep DJ/Admin/source credentials distinct; only public listener audio may be published.
- **Rights:** filename claims such as `[Copyright Free]` do not substitute for independent authorization to broadcast or redistribute media.
